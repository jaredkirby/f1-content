## Objective

Add reusable text-to-speech generation and optional Robot Voice Lab vocoder
processing while preserving exact event identity, evidence-bound scripts,
versioned outputs, caption synchronization and independent human voice review.
Generate clean speech once; reuse it for clean narration, effect revisions and
video rerenders.

## Architecture review

| Priority | Finding | Integration consequence |
| --- | --- | --- |
| High | [Speech handler](https://github.com/jaredkirby/robot-voice-lab/blob/99da340ae1dc37bdebcfe5f1e3e214548948251f/server/speech.mjs) returns a streamed MP3, without a persisted request/output receipt, audio validation or alignment. Its SDK retries are disabled and request timeout is 120 seconds. | Retain this bounded transport behavior, but add an immutable narration job/result contract. A 200 response alone cannot make narration render-ready; validate the complete audio and timing before publishing the result. |
| High | [Worker](https://github.com/jaredkirby/robot-voice-lab/blob/99da340ae1dc37bdebcfe5f1e3e214548948251f/dist/worker.js) normalizes the source and resamples to 22.05 kHz. [Saved generations](https://github.com/jaredkirby/robot-voice-lab/blob/99da340ae1dc37bdebcfe5f1e3e214548948251f/server/generations.mjs) accept only mono 22.05 kHz WAVs, and trust browser-submitted settings. | Saved dry WAV is an app derivative, not the original provider audio or a server-attested generation receipt. Preserve original provider bytes separately. An existing clip may be imported with honest provenance and unknown fields, never relabeled as a verified F1 provider run. |
| High | F1 [renderer](../../f1_pipeline/render.py) generates speech in approximately 12-word phrases, probes each duration, and uses those durations for caption frames, scene lengths and source end-frame holds. Voice Lab has no caption map; its vocoder can add an echo tail. | Replacing the speech call alone would break this timing contract. Prepare narration/timings first; use measured selected-audio duration and explicit tail accounting, preserving reviewed footage limits. |
| Medium | Voice Lab's cache is primarily browser memory; persisted clips restore a decoded source. Catalog choices are account-dependent, and a seed is only best-effort repeatability. | Use a persistent hash-verified F1 cache keyed by the effective generation request. Freeze explicit model/voice/settings per job; catalog changes never silently select a new voice. Reuse exact generated bytes rather than expecting a seed to reproduce them. |
| Medium | [DSP](https://github.com/jaredkirby/robot-voice-lab/blob/99da340ae1dc37bdebcfe5f1e3e214548948251f/dist/dsp.js) is directly loadable through CommonJS; browser/worker orchestration is unnecessary for batch processing. It peak-normalizes even with `wet: 0`, clamps some options and limits clips to 180 seconds. | Use an external headless processor with strict F1-side validation. Disabled means bypass DSP entirely. Preserve original audio and record effective settings and processor revision. Reject oversized inputs rather than silently trim them. |
| Medium | Voice Lab is [GPL-3.0-or-later](https://github.com/jaredkirby/robot-voice-lab/blob/99da340ae1dc37bdebcfe5f1e3e214548948251f/package.json); F1 declares MIT in [pyproject.toml](../../pyproject.toml). | Keep the Voice Lab implementation and notices in its independent repo for the pilot. ## Decisions

1. Keep Samantha as the existing default/reference until explicit human promotion.
   Add narration as a separate stage. Hosted speech execution is explicit and
   bounded; `render` and `run` never initiate paid generation as a side effect.
   Existing Samantha rendering remains compatible.
2. Support two independent selections: speech backend (`say`, imported audio,
   later ElevenLabs) and post-processing (`none` or `robot_vocoder`).
   Vocoder can process either generated or imported clean speech. Effect
   selection does not select a different speech provider.
3. Use Voice Lab for voice/settings exploration and its independent headless DSP
   tool for optional effects. F1 owns event contracts, prepared jobs, importing,
   caching, timings, rendering and review. Avoid browser automation and dependence
   on the private hosted Site as a pipeline service.
4. Preserve original MP3/WAV and decoded clean audio at the available source
   quality. Produce a 48 kHz mono renderer derivative using FFmpeg; upsampling does
   not recover lost detail. For initial automated vocoder parity, explicitly
   process at the app's 22.05 kHz rate. A 48 kHz DSP recipe is a separate later
   listening candidate, not an automatic quality upgrade.
5. Prefer scene-sized TTS requests for natural phrasing, with timestamp alignment
   reduced into readable caption phrases. Do not turn every 12-word caption into
   a paid request. The [ElevenLabs timing endpoint](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps)
   returns audio with character-level alignment; account/model behavior still
   needs an authorized pilot. Require an explicit reviewed timing map for
   imports lacking alignment. Never estimate speech timing by word count.
6. Pin actual effective voice options, normalization/pronunciation settings and
   applicable dictionary versions. Keep the editorial/display text separate from
   a pronunciation form; any spoken wording change requires review. Provider
   alignment of normalized speech must be mapped back to the intended captions.
7. Use the existing [human feedback](../model-workflows.md),
   [mobile review](../mobile-review.md) and [quality policy](../model-selection.md).
   Present one candidate output for approve/reject comments. Record voice and
   vocoder preferences with explicit scope; default promotion remains a separate
   decision after held-out evaluation.

## Proposed data and CLI contracts

The commands below are now implemented. See the [operator guide](../narration.md)
for their exact schema, preparation helper and execution examples.

| Contract | Proposed location/operation | Required behavior |
| --- | --- | --- |
| Request | `research/event/narration-request.json` | Exact event identity, plan hash, format/scene IDs, editorial and spoken text hashes, explicit provider/model/voice, effective settings, segmentation and timing strategy, pronunciation version, request/time/byte/character bounds and approved execution scope. |
| Offline preparation | `speech-prepare --request …` | Freeze canonical request bytes and identify cache hits/misses, total requests and submitted characters. Read no credential and make no provider call. Distinguish provider estimates/credits from attributable USD cost. |
| Generation | `speech-execute --request …` | Validate current request-bound authorization and budget, create execution intent before calling the provider, stop on ambiguity, persist success/failure receipts. No automatic retry of a possibly billed request. |
| Import | `speech-import --request … --bundle …` | Validate provided script/settings/event bindings and local audio/timing hashes. Preserve source/receipt attribution; unavailable provider cost or identity remains unknown. Refuse path escapes, stale plans and partial assets. |
| Effect recipe | `research/event/narration-effect.json` | Explicit `none` or vocoder selection and complete effective DSP settings; no hidden preset changes. Separate from speech cache identity and spending authorization. |
| Processing | `speech-process --request … --effect …` | Use validated clean assets and an explicit external processor revision. Compute a new derivative without TTS/network access; disabled path preserves the dry source. |
| Immutable results | `runs/narration/<job-id>/` | Frozen request, execution intent, sanitized provider receipt, original audio, clean WAV, alignment/caption map, optional vocoder WAV and effect receipt. Publish result manifest atomically after all required files validate. |
| Render selection | `research/event/narration-selection.json` | Hash-bound selected job/result, effect variant and per-format/scene audio/timings. Capture selection and all consumed assets in render input bindings. |
| Output provenance | Existing versioned video record and EDL | Actual speech/effect attribution, source and selected audio hashes, timing recipe and model-work receipt links. Replace hardcoded Samantha description for new backends. |

Receipt fields include job/attempt ID, exact event identity, request SHA-256,
plan/text hashes, provider/model/voice and observed revision when available,
effective settings, SDK/adapter version, start/end/elapsed time, provider request
ID when exposed, submitted characters, measured usage/credits/cost or null,
original and derivative hashes, sample count/rate/duration, timing bindings,
processor revision/options, source job and outcome. An operator declaration is
distinct from an observed provider result. Generation metadata supplied by the
Voice Lab browser cannot establish the actual upstream execution.

Cache identity includes canonical spoken text, provider/model/voice, effective
settings/seed, pronunciation/normalization, segmentation/context, output format
and adapter recipe. Event job receipts bind any reused asset to the exact event
and plan. Keep assets within the selected durable workspace; share within that
workspace only after full binding/hash validation. A separate effect cache uses
the clean PCM hash, processor code/revision, sample rate and effective DSP recipe.
A changed wet/dry mix, note, tempo or echo never invalidates the clean TTS cache.

Use an explicit credential route and provider-specific login-Keychain item,
following the existing [credential conventions](../credentials.md), without
reusing OpenRouter's secret. Review/prepare/render work reads no secret.
Catalog access remains an explicit operation; missing Voices/Models permissions
must not silently replace the requested voice. Never extract private Site
credentials or treat a stored key as spending authorization.

## Optional vocoder behavior and timing

Expose mode (single note, chord, melody, progression), MIDI root note, brightness,
consonant clarity, wet/dry mix, tempo, echo, progression name and beats per chord.
Persist resolved values rather than just a preset label. Speech speed belongs to
TTS; the current DSP does not implement speech time stretching.

For each format, stitch prepared clean scene audio with its frame-grid padding,
then process the contiguous narration track once. This preserves carrier phase
and chord/echo continuity across scenes and avoids adding a separate 0.6-second
echo pause after every scene. Split the result into renderer scene slices at the
recorded sample boundaries; keep any final echo tail on the final scene.
Different scripts/formats receive distinct track receipts; identical upstream
speech can be reused.

The current vocoder preserves the input time axis and adds 0.6 seconds when echo
is enabled. Keep speech captions on the source alignment, account for the tail
in audio/scene/EDL duration, and avoid extending spoken-word captions through a
silent decay. Round scene ends to the renderer's 24 fps grid. Preserve source
out-limits: longer audio uses the existing disclosed held end frame or prompts an
edit revision, never extends into unreviewed footage. Fail if duration behavior
differs from the pinned recipe. Any later effect that moves/time-stretches speech
requires a new explicit timing map.

`none` bypasses DSP and its normalization. `robot_vocoder` with zero wet mix is
still the selected processing recipe and must be labeled accurately.
Keep post-effect loudness/peak checks and the renderer's final normalization
pass; DSP peak normalization alone does not prove phone intelligibility.

## Verification and acceptance

Offline implementation regressions must establish:
- Invalid/stale identity, plan, text, selection, effect or audio hash fails closed.
- Modified or partial cached audio cannot be reused; malformed, nonfinite or
  absent timings cannot be used for captions.
- Render and effect edits make zero provider calls; effect revisions reuse the
  exact clean source and do not mutate it.
- No-op preserves bytes; DSP options are bounded; oversized input fails;
  effect output is finite and its measured sample count matches its receipt.
- Character alignment maps correctly to displayed text, monotonic caption ranges,
  frame-grid scenes and reviewed footage bounds; echo occurs only at the end
  of the assembled track.
- Failure/interruption preserves evidence, does not replace the authoritative
  result/manifest and does not automatically repeat a possibly billed call.
- Voice/effect changes make earlier audio, video, mobile-review and human feedback
  bindings stale; technical success never establishes approval.

Use mocked local provider endpoints with synthetic secrets. Run relevant
regressions followed by `scripts/check` once for code changes, and package checks
when adding resources/dependencies. Native rendering and phone listening remain
separate acceptance checks.

For this review, an isolated Node smoke check of the pinned DSP passed at
22,050 and 48,000 Hz using synthetic audio: identical runs matched; source input
was unchanged; float WAV round-trip matched; echo added exactly 0.6 seconds;
zero wet mix changed samples through normalization. This is a DSP check, not a
listening result. Upstream full tests and real SDK/provider execution were not
run. Local document links and the repository index guard passed. Diff whitespace
was checked and an extra trailing blank line was removed. The private review
